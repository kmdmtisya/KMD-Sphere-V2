# WealthSphere web portal

The desktop web channel of WealthSphere (phase P14, [ADR-0018](../docs/adr/0018-web-portal-architecture.md)): Next.js (App Router), React and TypeScript, with a Backend-for-Frontend (BFF) in the same server. Read [docs/web](../docs/web) before changing anything here.

**Rules that are checked in CI**
- **No financial logic.** The backend is authoritative. The web shows the decimal strings the API sends and never calculates money; `wealthsphere/no-money-arithmetic` enforces this (QG-26.3).
- **Colours only from tokens.** `wealthsphere/no-colour-literals` and `scripts/check-css-colours.mjs` reject colour literals outside `src/tokens`, so Light, Dark and System apply everywhere ([WEB_THEME_SYSTEM.md](../docs/web/WEB_THEME_SYSTEM.md)).
- **No tokens in the browser.** Access and refresh tokens stay on the server (BFF, from P14-T05). The proxy forwards only allow-listed `/api/v1/*` paths.
- **The API contract is generated.** `src/lib/api/schema.d.ts` comes from `backend/openapi.json`; CI fails on drift.

## Commands

| Command | What it does |
|---|---|
| `npm ci` | Install the locked dependencies (Node 20.9 or newer; CI uses Node 24) |
| `npm run dev` | Development server on http://localhost:3000 |
| `npm run lint` | ESLint (Next.js rules and the WealthSphere guards) and the CSS colour check |
| `npm run lint:selftest` | Proves the guards fire on the seeded violations in `lint-fixtures/` |
| `npm run typecheck` | Route types (`next typegen`) and `tsc --noEmit` |
| `npm test` | Unit tests (Vitest) |
| `npm run api:generate` / `api:check` | Regenerate the API client / fail if it drifted from `backend/openapi.json` |
| `npm run build` | Production build (standalone output for the container) |
| `npm run start:standalone -- --port 3100` | Run the production build the way the container does |
| `npm run e2e` | Playwright against the standalone server |

## Configuration

| Variable | Default | Meaning |
|---|---|---|
| `WS_API_BASE_URL` | `http://127.0.0.1:8000` | The API the BFF calls server to server. https, or http to a loopback address only |
| `WS_OIDC_ISSUER` | — | The Keycloak realm, for example `http://127.0.0.1:8081/realms/wealthsphere` |
| `WS_OIDC_CLIENT_ID` | `wealthsphere-web` | The BFF's confidential client |
| `WS_OIDC_CLIENT_SECRET` | — | **Secret.** Generated by Keycloak; kept in the secret store (local: `web/.env.local`) |
| `WS_SESSION_KEY` | — | **Secret.** 32 random bytes, base64url: seals the sessions in Redis and the sign-in transaction |
| `WS_REDIS_URL` | — | The session store |
| `WS_PUBLIC_URL` | — | The portal's public origin; the callback and logout URLs derive from it |
| `WS_SESSION_IDLE_SECONDS` / `WS_SESSION_ABSOLUTE_SECONDS` | `1800` / `36000` | Session lifetimes, matching the realm's idle (30 min) and maximum (10 h) SSO lifetimes |
| `WS_E2E_EXPECT_API` | unset | `1` makes the e2e health test require the API (CI) |
| `WS_E2E_AUTH`, `WS_E2E_PASSWORD` | unset | `1` and the seeded test users' password run the sign-in journeys against the full stack (CI) |
| `WS_PLAYWRIGHT_CHANNEL` | unset | `chrome` uses an installed Google Chrome when Playwright cannot download its own browser |

**Locally:** start the stack, then run `python scripts/keycloak_dev.py seed-users` and `python scripts/keycloak_dev.py web-client`. The second command registers the client in the running realm and writes `web/.env.local` (git-ignored) with the issuer, the client secret, a new session key and the Redis URL. No secret is ever committed.

## Sign-in and sessions (P14-T05)

- `/api/auth/login` starts the Authorization Code flow with PKCE, state and nonce. `/api/auth/callback` exchanges the code server to server and creates the session.
- Tokens stay in Redis, sealed with AES-256-GCM. The browser holds only `__Host-ws_session` (HttpOnly, Secure, SameSite=Lax) and the readable CSRF token `__Host-ws_csrf`.
- Every state-changing request needs the portal's Origin and the CSRF token (header `X-CSRF-Token` or form field `csrf`).
- `/api/proxy/*` forwards allow-listed `/api/v1/*` calls with the session's token, refreshing it 30 s before expiry. A failed refresh ends the session.
- `/api/auth/logout` (POST) deletes the session, revokes the refresh token and ends the Keycloak session. `/api/auth/session` reports the user and the expiry times, never a token.
