# API Conventions

Contract source: OpenAPI generated by FastAPI (`/api/v1`). Every API change needs typed Pydantic request/response schemas and an updated, committed `openapi.json` (checked in CI, P01-T14).

## Versioning and style
- Prefix `/api/v1`. Breaking changes require `/api/v2`.
- Resource-oriented REST, plural nouns, lowercase kebab-case paths, `snake_case` JSON fields.
- Timestamps are ISO 8601 UTC (`2026-10-09T12:00:00Z`); dates are `YYYY-MM-DD`.

## Money, quantities and rates
- Money is an object `{ "amount": "1234.50", "currency": "USD" }` with the amount as a **string**; quantities and rates are strings as well. Never JSON numbers.
- Currency codes are ISO 4217. Amounts are rounded per ADR-0006 and each field documents its precision.
- Responses derived from market data carry `as_of` (and provider when relevant) so clients can show freshness.

## Errors
RFC 7807 `application/problem+json`:

```json
{ "type": "https://wealthsphere.app/problems/validation", "title": "Validation failed", "status": 422,
  "detail": "…", "correlation_id": "…", "errors": [{ "field": "amount", "message": "…" }] }
```
Statuses: 400/422 validation, 401 unauthenticated, 403 forbidden, 404 not found (also used where revealing existence would leak data, see the authorization ADR), 409 conflict/idempotency, 429 rate limited with `Retry-After`.

## Authentication and authorization
Bearer JWT from Keycloak on every request except health endpoints. Ownership is verified server-side for every resource id. Cross-user access is covered by tests.

## Correlation and idempotency
- `X-Correlation-ID` is accepted or generated and echoed in responses and logs.
- Ledger-posting and other non-idempotent POSTs accept an `Idempotency-Key` header; replays return the original result.

## Pagination and filtering
Cursor pagination: `?limit=50&cursor=…`, response `{ "items": [], "next_cursor": null }`. Filters are explicit query parameters; sort via `sort=field` or `sort=-field`.

## Health
`GET /health/live` (process up), `GET /health/ready` (database and Redis reachable). Not authenticated, no sensitive detail.

## Streaming
AI chat uses server-sent events with typed events (`token`, `tool`, `source`, `done`, `error`).

## Rate limits
Per-user and per-IP limits; authentication endpoints are stricter. Limits are documented in OpenAPI descriptions.
